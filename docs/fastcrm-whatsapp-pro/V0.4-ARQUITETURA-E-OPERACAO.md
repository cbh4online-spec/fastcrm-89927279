## Fluxo
```text
Painel --AUTH_START--> SW: state + verifier (getRandomValues), challenge S256
SW --launchWebAuthFlow(interactive)--> /oauth/authorize --> login /auth + consentimento /.lovable/oauth/consent
callback https://<id>.chromiumapp.org/oauth2?code&state --> validação exata (origem, caminho, state, code único, sem error)
SW --POST form-urlencoded (grant_type, client_id, redirect_uri, code_verifier, code)--> /oauth/token (timeout 15 s)
token validado --> chrome.storage.session  |  Painel recebe só {status}
```

## Garantias
- Tokens só no service worker e `chrome.storage.session` (apagados ao fechar o browser). Nunca local/sync, DOM ou respostas.
- Sem refresh token nesta versão: expirado (margem 30 s) = «Desligado», sessão apagada.
- Remetente: `sender.id === runtime.id`, sem `sender.tab`, `sender.url === chrome-extension://<id>/sidepanel.html`.
- Mensagens: OPEN_TAB (allowlist), AUTH_STATUS, AUTH_START, AUTH_LOGOUT, CONTACT_LOOKUP (recusado: `api_indisponivel`).
- Permissões: storage, sidePanel, identity; host_permissions só `https://eumnfkccyvlyoyjchiwe.supabase.co/*`; CSP `connect-src` só essa origem.
- Login só por clique; telefone nunca sai do painel nem vai para storage/URL/logs.

## Setup manual do cliente OAuth (a fazer por um administrador, não feito)
1. Carregar a extensão (Load unpacked) e anotar o ID; o redirect é `https://<ID>.chromiumapp.org/oauth2`. Para ID estável entre máquinas, fixar `key` no manifest numa iteração própria.
2. Habilitar o OAuth Server do backend do FastCRM com consent path `/.lovable/oauth/consent` (pedido explícito ao agente/administrador; não foi executado).
3. Registar cliente **público** (sem secret), PKCE obrigatório, redirect exato acima, scopes `email` (sem `openid` até haver chaves assimétricas verificadas).
4. Colocar o client_id público em `lib/oauth-config.js` → `PUBLIC_CLIENT_ID`, correr `npm test` e empacotar com `node scripts/package-extension.mjs --dist-only`.
