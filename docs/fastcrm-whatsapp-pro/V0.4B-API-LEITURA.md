## Contrato
`POST` JSON (≤1 KB, `Content-Type: application/json`, `Authorization: Bearer <access_token OAuth>`):
- `{"action":"workspaces"}` → `{workspaces:[{id,name,role}]}` (só memberships com `crm.read`, máx. 50).
- `{"action":"lookup","workspace_id":"<uuid>","phone":"..."}` → `{workspace_id, contacts:[{id,workspace_id,name,phone,company}], leads:[{id,workspace_id,name,phone,status}], exhaustive:false}` (máx. 10 por fonte).
- Qualquer outro campo/ação → 422. Não existe envio de mensagens nem escrita.

## Controlos
| Controlo | Implementação |
|---|---|
| Ativação | `FASTCRM_WA_EXTENSION_API_ENABLED === "true"` + client_id + origem válidos, senão 503 |
| CORS | Só `Origin` igual a `FASTCRM_WA_EXTENSION_ALLOWED_ORIGIN` (`chrome-extension://<32 a-p>`); outra → 403. `Vary: Origin`, métodos POST/OPTIONS, sem credentials |
| Autenticação | `auth.getClaims(token)` (verificação de assinatura) + `exp` + `role=authenticated` + `client_id` exato do JWT + `auth.getUser(token)` com `id === sub` |
| Autorização | Membership explícita em `workspace_members` com `crm.read` (`_shared/capabilities.ts`). **Sem bypass super admin** |
| Instâncias | `workspace_instances`: `suspended/inactive` → 403; `supabase_url` diferente → 409 `workspace_instance_unsupported`; erro de leitura → 503 |
| Dados | Cliente com o token do utilizador (RLS aplica-se); **sem service_role**. Filtros `eq workspace_id`, `deleted_at/archived_at is null`, `in` com variantes derivadas (sem ilike). Filtro defensivo de `workspace_id` na resposta |
| Abuso | 1 KB, timeout 10 s (504), 30 pedidos/min por utilizador (por isolate, melhor esforço → 429) |
| Respostas | `Cache-Control: no-store`, erros genéricos, sem logs de token/telefone/nomes |

Códigos: 401 token, 403 client/origem/membership/suspenso, 409 instância externa, 413/415/422 entrada, 429, 503 desativada/indisponível, 504 timeout. Zero resultados nunca é confirmação absoluta (`exhaustive:false`).

## verify_jwt
Não foi adicionada entrada em `supabase/config.toml`. Na infraestrutura Lovable as funções são publicadas por omissão com `verify_jwt = false`; por isso a função valida **sempre** o token em código (getClaims + getUser). Não depende do gateway.

## Limitações conhecidas
- Control Plane externo (`resolveWorkspaceTarget` com Control Plane ativo) não é consultado; só `workspace_instances` local. Workspaces geridos apenas pelo Control Plane exigem revisão antes do rollout.
- Não confirmado que `workspaces(name)` é legível via RLS para todos os papéis (se não for, `name` vem `null`).
- Não confirmado que os tokens OAuth emitidos incluem `client_id` e são aceites pelo PostgREST/RLS. **Teste live pendente.**
- Rate limit em memória não é global.
- RLS antiga 0079 continua por resolver (não tocada).
